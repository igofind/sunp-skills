# JavaScript 审查规则

以 Google JavaScript Style Guide 为基础，Airbnb JavaScript Style Guide 为补充，按下列维度审查。两者冲突时以项目现有配置为准，无配置时以 Google 规范为准。

## 源文件结构

- UTF-8 编码；文件名能表明内容
- `@fileoverview` JSDoc 按需置于文件顶部
- 使用 ES 模块，导入顺序清晰

## 格式与语言特性

- 缩进为 4 个空格，列宽上限 80
- 变量声明、数组与对象字面量、类、函数、字符串与数字字面量写法符合规范
- 控制结构简洁；相等检查使用规范要求的比较方式
- `this` 使用明确；不使用规范列出的禁用特性

## Airbnb 补充项

- 优先 `const`，避免 `var`；对象与数组用字面量，不用构造函数
- 解构用于多属性访问；字符串用单引号，拼接用模板字符串
- 函数优先具名声明或箭头函数，避免修改参数
- 模块用 `import`/`export`，不用 `require`
- 空白、逗号、分号、类型转换符合约定
- 命名：变量与函数 lowerCamelCase，类 PascalCase，常量可大写；避免单字母名（循环计数器除外）

## 命名

- 名称完整达意，大小写符合规范
- 同类实体命名方式一致；不使用含义不明的缩写

## 注释与文档

- 文件、类、方法与函数按需提供 JSDoc，说明用途与行为
- 注释解释原因而非复述代码，与实现同步
- 公开 API 的文档说明参数、返回值与副作用

## 策略

- 规范未规定处以项目现有风格为准
- 编译器警告须处理；弃用标记清晰
- 生成代码可豁免人工风格要求
