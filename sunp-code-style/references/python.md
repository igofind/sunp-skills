# Python 审查规则

以 PEP 8 为基础，Google Python Style Guide 为补充，按下列维度审查。两者冲突时以项目现有配置（如 lint 配置）为准，无配置时以 PEP 8 为准。

## 排版

- 缩进用 4 个空格，不用 Tab，不混用 Tab 与空格
- 行宽上限 79；文档字符串与注释上限 72；项目可约定放宽至 99，但注释与文档字符串仍保持 72
- 续行优先用括号内的隐式续行；长条件不与嵌套代码视觉冲突
- 空行、导入顺序、源文件编码符合规范
- 字符串引号、表达式与语句中的空白符合 PEP 8

## 命名

- 模块与包名小写短名；类名 CapWords；函数、方法、变量 lower_with_under
- 常量 UPPER_WITH_UNDER；异常名以 Error 结尾
- 名称达意，避免易混淆字符；单下划线表内部，双下划线触发名称改写

## 注释与文档字符串

- 块注释、行内注释与文档字符串符合 PEP 257
- 注释解释原因，文档字符串说明用途、参数、返回值与行为
- 注释与实现同步；过时的 TODO 与注释指出

## 语言实践（Google 补充）

- 使用 lint 工具；导入只用 `import x` 或 `from x import y`，不用通配符导入
- 不用可变对象作默认参数；异常不忽略
- 生成器、lambda、条件表达式、装饰器用法符合规范
- 类型注解按需提供，不引入无意义注解

## 策略

- 项目已有风格与规范冲突时，指出冲突并说明依据，不假设项目一定正确
- 不为兼容旧版本而牺牲可读性；不为符合规范破坏向后兼容
