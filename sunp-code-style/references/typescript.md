# TypeScript 审查规则

以 Google TypeScript Style Guide 为基础，按下列维度审查。

## 源文件结构

- UTF-8 编码
- 版权信息、`@fileoverview` JSDoc 按需置于文件顶部
- 导入与导出顺序清晰，类型导入使用对应的 type 导出形式
- 文件名能表明内容，与模块用途一致

## 格式与语言特性

- 缩进为 4 个空格；行宽、换行、空白符合项目 Prettier 或等价配置，无配置时保持文件内一致
- 局部变量声明、数组与对象字面量、类、函数写法符合规范
- `this` 使用明确；控制结构简洁；不使用规范列出的禁用特性
- 装饰器用法符合约定

## 命名

- 标识符完整达意，大小写符合 TypeScript 惯例
- 类型、接口、类、方法、变量按各自规则命名，同类实体方式一致

## 类型系统

- 优先使用类型推断，不写可由上下文推出的显式类型
- `undefined` 与 `null` 使用符合规范；优先结构类型
- 优先用 interface 表达可扩展的类型，慎用 type 别名
- 数组用 `Array<T>`；索引签名、映射类型、条件类型用法符合约定
- 限制 `any`、`{}`、包装类型与仅用于返回值的泛型；确需使用时有理由

## 注释与文档

- 模块顶层导出、类、方法与函数按需提供 JSDoc，说明用途、用法与行为
- JSDoc 标签与换行符合规范，注释确实提供额外信息，不复述签名
- 注释置于装饰器之前；注释与实现同步

## 策略

- 规范未规定处以项目现有风格为准
- 弃用标记清晰；生成代码可豁免人工风格要求
