# 项目现状文档

## 用途

给一个现有仓库，只读扫描后按技术主题产出多篇独立的项目现状文档，帮接手的人查到项目全貌、功能、数据、接口与源码位置。文档是供人查阅的参考手册，按主题拆成独立文件；每篇内容完整自洽，不靠互相引用拼凑。

用简体中文。写作、排版与表达规则见 `references/writing.md`；各主题骨架见 `references/templates.md`。

## 边界

- 只读：不改业务代码与配置；文档默认写入 `docs/` 下的子目录，具体路径在阶段一给出建议并经用户确认，项目已有文档目录约定或用户指定路径时沿用。
- 先选后写：先给出文档选项，用户选完才生成；未确认前不写文档文件。
- 不编造：证据不足的标注出来，不把静态代码证据写成线上运行事实。

## 与相邻 skill 的边界

- 本 skill 产出给人查阅的项目现状参考手册，用于接手时建立整体认识、需要时按主题查细节。
- 单个功能的内部结构、实现细节清单与代码双向翻译用 `sunp-doc-feature`。
- 已有文档的表达、语法与阅读体验审查润色用 `sunp-doc-check`。

## 流程

复制下列清单逐项推进，每项完成后再进入下一项：

```
阶段一
- [ ] 只读扫描仓库，记录证据与缺口
- [ ] 输出文档选项及建议组合
- [ ] 停止，等待用户选择

阶段二
- [ ] 按选中的文档逐篇生成
- [ ] 按写作要求逐项自检
- [ ] 不合格则修正并复检
- [ ] 输出简短交付说明
```

## 输入解析

调用时若随 skill 附带了文字（如 `/sunp-doc-project 整理当前项目` 中的「整理当前项目」），视为分析范围描述：明确指向某个项目路径或仓库时直接采用；只说「当前项目」时以当前工作目录为准；描述含糊时按阶段一先问清楚。没有附带文字时同样在阶段一确认范围。

## 阶段一：扫描与选项

先只读扫描仓库：README、构建文件、应用入口、模块与依赖、配置、数据定义、接口与交互、代码组织。按项目规模调整深度，超大项目按模块抽样并说明覆盖范围。扫描细则见 [`references/scanning.md`](references/scanning.md)。

输出文档选项：按调研结果逐项标注「建议 / 可选 / 不建议」及理由，给出建议组合，然后停止等待用户选择。清单与输出格式见 [`references/planning.md`](references/planning.md)。

## 阶段二：生成

按选中的文档逐篇生成，一个主题一个独立文件，写入阶段一确认的输出目录。各类文档的骨架见 [`references/templates.md`](references/templates.md)，内容、排版与表达要求见 [`references/writing.md`](references/writing.md)。

按信息形态选承载方式：二维数据用短表格，目录、配置、命令、SQL、代码用代码块，架构与关系用 mermaid 图，一维清单用列表；长路径不塞进表格单元格。

自检按 [`references/writing.md`](references/writing.md) 的清单逐项过：主题是否完整、定位线索是否清楚、有没有臆造、表格是否简短且有引导、排版是否得当、表达是否易读。任一项不合格就当场修改并重新自检，全部合格后才输出交付说明。

交付说明列出：生成的文档文件路径、扫描覆盖范围、跳过的文档及原因、待确认事项。

## 文档选项清单

- 基础层：项目概览、功能清单、架构设计
- 专题层：数据库设计、接口清单、部署说明、子系统专题（按实际子系统拆多篇）

按调研结果取舍，不默认全选。完整清单与生成条件见 [`references/planning.md`](references/planning.md)。
