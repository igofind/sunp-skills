# 项目现状文档

## 用途

给一个现有仓库，只读扫描后产出少量、能追溯源码的项目现状文档，帮接手的人看清全貌并找到深入阅读的入口。

文档给人看，用简体中文和中文语法，符合中文阅读习惯：先结论后展开，源码标识保留原文。

## 边界

- 只读：不改业务代码与配置，文档只写入 `docs/00 项目整体概览/`。
- 先选后写：先给出文档选项，用户选完才生成。
- 不编造：证据不足的标注出来，不把静态代码证据写成线上运行事实。

## 流程

阶段一：扫描 → 给出文档选项 → 停止，等待用户选择
阶段二：按选中的文档生成 → 自检 → 交付

## 阶段一：扫描与选项

先扫读仓库：README、构建文件、应用入口、模块与依赖、配置、数据定义、接口与交互、代码组织。按项目规模调整深度，超大项目按模块抽样并说明覆盖范围。扫描细则见 [`references/scanning.md`](references/scanning.md)。

输出文档选项：按调研结果从候选菜单中逐项标注「建议 / 可选 / 不建议」及理由，给出建议组合，然后停止等待用户选择。格式与候选菜单见 [`references/planning.md`](references/planning.md)。

## 阶段二：生成

按选中的文档生成，写入 `docs/00 项目整体概览/`。写作要求见 [`references/writing.md`](references/writing.md)。

写完后自检：结论是否清楚、关系是否讲明、是否有深入阅读入口、有没有臆造；不合格的当场修，再输出一份简短交付说明。

## 文档候选菜单

- 基础层：一页速览、架构与模块
- 专题层：核心业务与流程、数据模型、外部依赖与交互、配置与研发导航、关键决策与风险、术语表

按调研结果取舍，不默认全选。完整清单与输出格式见 [`references/planning.md`](references/planning.md)。
