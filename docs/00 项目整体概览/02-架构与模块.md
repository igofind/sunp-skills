# 架构与模块

## 结论

仓库按工作场景划分模块，每个 skill 独占一个目录，目录即模块边界。模块之间没有运行时依赖，只有文档层面的引用与分工约定。

## 模块清单

| 模块 | 职责 | 文件位置 | 关联模块 |
| --- | --- | --- | --- |
| 仓库入口 | 声明定位、skill 清单与加载目录约定 | `README.md` | 场景台账、参考资料索引 |
| 场景台账 | 记录工作场景与 skill 的对应关系及状态 | `工作场景.md` | 三个 skill |
| 项目现状文档 | 只读扫描仓库，按主题生成项目现状文档 | `sunp-doc-project/SKILL.md` | 边界声明引用另两个 skill |
| 指定功能文档 | 针对单个功能生成结构化文档，支持代码与文档双向翻译 | `sunp-doc-feature/SKILL.md` | 边界声明引用项目现状文档 |
| 文档表达审查 | 审查已有文档的表达、语法、风格与阅读体验 | `sunp-doc-check/SKILL.md` | 无 |
| 参考资料索引 | 汇总各 skill 参考资料台账的入口 | `参考资料.md` | 项目现状文档台账 |

## 关键关系

三个 skill 通过各自 `SKILL.md` 的边界声明区分职责：项目全景归 `sunp-doc-project`，功能细节与双向翻译归 `sunp-doc-feature`，表达层审查归 `sunp-doc-check`。声明位置见 `sunp-doc-project/SKILL.md`（与相邻 skill 的边界）与 `sunp-doc-feature/SKILL.md`（与其他 skill 的边界）。

`工作场景.md` 把 5 个工作场景映射到 skill，并标记 2 个待建场景。参考资料按 skill 分散存放，根目录 `参考资料.md` 只做索引；`sunp-doc-project/参考资料.md` 记录该项目 skill 的设计依据与来源。
