# 功能画像

## 用途

`sunp-doc-project` 给出项目全景；本 skill 从全景里选一个功能钻下去，产出给人看的功能画像。主线是三件事：从业务功能名定位代码入口，界定范围，按主题写成多篇独立文档。

## 边界

- 只读：不改业务代码与配置；文档默认写入 `docs/01 功能画像/<功能名>/`，项目已有文档目录约定或用户指定路径时沿用。
- 先确认后写：先给出入口清单与文档选项，用户选完才生成；未确认前不写文档文件。
- 不编造：结论要能回到代码或配置；证据不足的标注为待确认。
- 证据可核对：路径相对文档所在仓库根，符号写到能找到，不写行号；框架行为与不可达分支标为推断。

## 与相邻 skill 的边界

- `sunp-doc-project` 产出给人看的项目全景，用于建立整体认识。
- 本 skill 深入单个功能，产出给人看的功能画像，不产出给 AI 翻译回代码的中间表示。
- `sunp-doc-check` 用于已有文档的表达层审查与润色。

## 流程

复制下列清单逐项推进，每项完成后再进入下一项：

```
阶段一
- [ ] 确认功能名称与项目范围
- [ ] 按线索面定位入口，判定功能粒度
- [ ] 识别各项目的角色与跨进程边界
- [ ] 输出入口清单、调研发现与文档选项
- [ ] 停止，等待用户选择

阶段二
- [ ] 按选中的文档逐篇生成
- [ ] 按写作要求逐项自检
- [ ] 不合格则修正并复检
- [ ] 输出交付说明
```

## 输入解析

调用时若随 skill 附带了文字（如 `/sunp-doc-feature 员工管理` 中的「员工管理」），视为功能名称；同时给出项目路径时一并采用。解析结果在阶段一确认：明确则直接作为分析对象，含糊则问清楚。没有附带文字时按阶段一先问功能名称与项目范围。

文字给出的是接口、表名或报错信息而不是功能名时，以该符号为锚点反向扩散到功能边界，并在调研发现里说明这是锚点式定位。

## 阶段一：定位与选项

定位方法见 [`references/locating.md`](references/locating.md)：按声明面、订阅面、配置面、数据面、调用面检索，至少两条独立线索指向同一批符号才算成立；一个画像以一个业务实体加它的主写操作为界，超界时给拆分建议；零匹配与多匹配的处理也在该文件。扫描维度与证据规则见 [`references/scanning.md`](references/scanning.md)。

阶段一交付三样东西：入口清单、调研发现、文档选项。入口清单一类入口一行，供用户核对范围；范围判定为需要拆分时，附拆分建议与依据。

输出后立即停止，等用户选择。清单与输出格式见 [`references/planning.md`](references/planning.md)。

## 阶段二：生成

按选中的文档逐篇生成，一个主题一个独立文件，写入阶段一确认的输出目录。各类文档的骨架见 [`references/templates.md`](references/templates.md)，写作、主责与表达要求见 [`references/writing.md`](references/writing.md)；示例见 [`examples/01-功能概览.md`](examples/01-功能概览.md)、[`02-流程与逻辑.md`](examples/02-流程与逻辑.md)、[`03-代码地图.md`](examples/03-代码地图.md)、[`07-跨项目链路.md`](examples/07-跨项目链路.md)。

自检按 [`references/writing.md`](references/writing.md) 的清单逐项过；任一项不合格就当场修改并重新自检，全部合格后才输出交付说明。

交付说明列出：生成的文档文件路径、扫描覆盖范围、跳过的文档及原因、待确认事项。

## 文档选项清单

- 基础层：功能概览、流程与逻辑、代码地图
- 专题层：上下游与中间件、数据与存储、异常与边界、跨项目链路

按调研结果与输入规模取舍，不默认全选。跨项目链路的生成条件是存在跨仓库或跨服务调用，不由输入项目数量决定。完整清单、分工与输出格式见 [`references/planning.md`](references/planning.md)。
