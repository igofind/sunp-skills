# 功能深度画像

## 用途

`sunp-doc-project` 给出项目全景；本 skill 从全景里选一个功能钻下去，产出给人看的深度画像。输入多个项目时，以功能为主线串起跨项目链路。

按主题拆成多篇独立文档，每篇完整自洽。

## 边界

- 只读：不改业务代码与配置；文档默认写入 `docs/01 功能画像/<功能名>/`，项目已有文档目录约定或用户指定路径时沿用。
- 先确认后写：先给出文档选项，用户选完才生成；未确认前不写文档文件。
- 不编造：结论要能回到代码或配置；证据不足的标注为待确认。

## 与相邻 skill 的边界

- `sunp-doc-project` 产出给人看的项目全景，用于建立整体认识。
- 本 skill 深入单个功能，产出给人看的功能画像，不产出给 AI 翻译回代码的中间表示。
- `sunp-doc-check` 用于已有文档的表达层审查与润色。

## 流程

复制下列清单逐项推进，每项完成后再进入下一项：

```
阶段一
- [ ] 确认功能名称与项目范围，定位入口与涉及代码
- [ ] 多项目时识别各项目在功能中的角色
- [ ] 输出文档选项及建议组合
- [ ] 停止，等待用户选择

阶段二
- [ ] 按选中的文档逐篇生成
- [ ] 按写作要求逐项自检
- [ ] 不合格则修正并复检
- [ ] 输出交付说明
```

## 输入解析

调用时若随 skill 附带了文字（如 `/sunp-doc-feature 员工管理` 中的「员工管理」），视为功能名称；同时给出项目路径时一并采用。解析结果在阶段一确认：明确则直接作为分析对象，含糊则问清楚。没有附带文字时按阶段一先问功能名称与项目范围。

## 阶段一：范围确认与选项

先确认输入：功能名称，以及一个或多个项目路径。按功能名定位入口（HTTP、RPC、消息、定时任务、事件等）与涉及的文件、类、方法，确定分析范围。多项目时先识别各项目在功能里的角色，如入口方、服务方、数据方。

扫描维度见 [`references/scanning.md`](references/scanning.md)，证据与范围说明写入调研发现。

输出文档选项：按调研结果逐项标注「建议 / 可选 / 不建议」及理由，给出建议组合，然后停止等待用户选择。清单与输出格式见 [`references/planning.md`](references/planning.md)。

## 阶段二：生成

按选中的文档逐篇生成，一个主题一个独立文件，写入 `docs/01 功能画像/<功能名>/`。写作要求见 [`references/writing.md`](references/writing.md)，各类文档的骨架见 [`references/templates.md`](references/templates.md)；完整示例见 [`examples/`](examples/01-功能概览.md) 与 [`02-流程与逻辑.md`](examples/02-流程与逻辑.md)。

自检按 [`references/writing.md`](references/writing.md) 的清单逐项过；任一项不合格就当场修改并重新自检，全部合格后才输出交付说明。

交付说明列出：生成的文档文件路径、扫描覆盖范围、跳过的文档及原因、待确认事项。

## 文档选项清单

- 基础层：功能概览、流程与逻辑、代码地图
- 专题层：上下游与中间件、数据与存储、异常与边界、跨项目链路

按调研结果与输入规模取舍，不默认全选。完整清单与输出格式见 [`references/planning.md`](references/planning.md)。
