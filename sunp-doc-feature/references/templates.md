# 阶段二：文档骨架

一个主题写一篇独立文档，按主题边界拆分，不按字数切分。每篇包含该主题完整的结论、关键依据与适用边界，读者只读这一篇就能理解；「深入阅读」只做导航，不替代本篇内容，且只链接本次实际生成的文档，不为未生成的文档预留链接。单篇过大时新增主题文档，不把同一主题切成互相引用的碎片。

每篇文档按对应骨架写。`[...]` 为待填占位；不需要的小节直接删除，不留空标题。标题层级不超过三级，类名、方法名、配置项、路径、命令保留原文。

## 通用规则

**证据写法**：`路径#符号`。路径相对文档所在仓库根，不带 `../`，不从工作目录或父目录起算；跨仓库引用在路径前加项目目录名，例如 `renzi-data-handler/app-job/src/main/java/.../ApiUcController.java#addBusinessCircleMentorShip`。符号默认写方法名或 XML 语句 id，同名方法按参数类型区分，一个文件含多个类时写成 `类.方法`。

不写行号。需要定位到具体语句时，用方法名、条件描述或相邻符号说明位置。代码可见的事实与推断分开写，框架默认行为与不可达分支标「推断」，并写出依据。

**表格与正文**：表格承担核对，正文承担关系。每张表之后用一段正文说明这些行的顺序、因果或异常，不把表格单独留在小节里。

**项目列**：涉及范围、关键代码位置等表都带「项目」列。输入为单个项目时该列写当前项目名，不改用「模块」「层级」等其他口径；输入多个仓库时写仓库目录名。

**深入阅读**：只列本次实际生成的文档，用相对路径链接，链接后写一句话说明该篇讲什么。

文件按 `序号-名称.md` 命名，序号沿用文档选项清单：`01-功能概览.md`、……、`07-跨项目链路.md`。文档之间用相对路径链接。
