# 阶段二：写作

文档给人看，用简体中文和中文语法，符合中文阅读习惯：先结论后展开，按读者理解顺序组织，不写英文直译腔；类名、方法名、配置项、路径、命令保留原文。

## 表达规则

产出的是解释型文档，目标是让人理解功能现状与关系。只陈述事实、结论与依据，不写操作步骤，不穷举接口清单。

以下规则让句子更易读、易懂，适用于全部文档。规则已列全，按本清单执行，审查时不需访问外部链接；规则出处见本 skill 的参考资料台账。

**人称与视角**

- 描述事实时以项目、模块、服务、接口为主语，用第三人称或无主语句，不用「你」。
- 只在需要读者执行操作时用祈使句，不必刻意加「你」。
- 不用「我们」；「用户」只指软件的使用者，不指文档读者。
- 全文主语视角保持一致。

**语态与句式**

- 用主动语态，让做动作的人或模块作主语；少用「被」字句，只有强调对象或执行者无关时才用被动。
- 先说条件、场景或目标，再说动作，让读者能跳过与自己无关的部分。
- 描述一般行为用现在时或习惯性陈述，不写「将会」等将来时推测。

**简洁与标题**

- 先给结论和下一步，再补依据；关键词前置，便于扫读。
- 删掉铺垫、套话、重复和与当前主题无关的内容；避免「你可以」「有……」等弱写法，直接以动词开头。
- 标题写清本节讲什么或得出什么结论，同级句式一致；标题末尾不加句号或冒号。

**每篇内容**

- 每篇回答三个问题：结论是什么、关系是什么、深入阅读去哪里
- 按 `templates.md` 的骨架组织内容；不需要的小节删掉，不留空标题
- 按主题拆分，不按字数机械切分；单篇过大时新增主题文档并补进文档选项，不把同一主题切成互相依赖的碎片
- 每篇独立完整：读者只读本篇就能拿到本主题的全部结论与必要依据；跨文档链接只用于导航，不用「详见 XX」替代本篇该写的内容
- 结论性概述可在多篇出现，关键依据与细节只在主责文档展开，主责划分见下节
- 「深入阅读」只链接本次实际生成的文档，不为未生成的文档预留链接
- 给出源码路径等定位线索，不复制大段源码，不穷举全部类、方法、表、接口
- 表格之后写一段正文说明顺序、因果或异常，不让表格单独承担解释
- 证据不足的明确标注，不把静态代码证据写成线上运行事实

## 主责矩阵

每篇只展开自己的主责内容，其他篇出现的同主题表述止步于一句结论。

| 主题 | 主责内容 | 其他篇只做什么 |
|---|---|---|
| 功能概览 | 定位、边界、触发方式总览 | 不重复主流程与分支 |
| 流程与逻辑 | 主流程步骤、关键分支、业务规则、关键实现点六维 | 不复述步骤，只引用一条主流程概述 |
| 代码地图 | 调用链图、分层与包职责、关键类型承载的字段与读写方 | 不复述分支与规则 |
| 上下游与中间件 | 外部依赖清单、中间件类型与用途 | 不画调用顺序 |
| 数据与存储 | 实体、表与缓存结构、读写路径、数据流转 | 不重复状态机与校验规则 |
| 异常与边界 | 错误码、边界条件、失败恢复 | 不重复校验规则明细 |
| 跨项目链路 | 跨进程边界、调用顺序、数据归属 | 不复制单项目内部步骤 |

入口清单整体只出现在「功能概览」的触发方式一节；其他篇需要提入口时写一句总述。

## 关键实现点

六维清单只在「流程与逻辑」一篇展开，代码地图不重复。每条具体、可验证，粒度到「不知道就会理解错」的层级。每个维度都明确回答有或没有，不适用也要标注，不能跳过：

| 维度 | 要记录的细节 |
|---|---|
| 数据转换 | 名称与编码映射、格式与类型转换 |
| 校验规则 | 必填、格式、范围、唯一性 |
| 校验失败处理 | 中断还是继续、错误信息、错误数据收集 |
| 状态流转 | 状态枚举、转换条件、非法转换处理 |
| 外部交互 | 接口调用、消息发送、缓存操作 |
| 边界条件 | 空值、并发、超时、部分失败 |

## 跨进程标注

每处结论标注所属项目：用项目名或仓库目录名标识，例如「订单服务（order-service）调用库存接口」。

不用「业务系统」「上游」「下游」这类统称指代具体项目。两个项目的代码高度相似或来自复制时，分别标注并说明差异，不合并成一条结论。

跨进程链路按功能主线组织，不按项目分块罗列。

## 自检与修正

逐项检查，任一项不合格就按问题当场修改，修改后重新从头检查，直到全部合格再交付：

- [ ] 结论清楚：每篇开头能直接读出结论，不需读者归纳
- [ ] 关系讲明：流程、代码、上下游、数据之间的关联有说明，表格后有正文
- [ ] 深入阅读入口：每篇给出可点击的相邻文档链接或源码路径，且无死链
- [ ] 证据可核对：每条路径能在对应仓库打开，符号能在该文件中找到
- [ ] 无行号：全文不含 `#数字` 形式的行号
- [ ] 推断已标注：框架默认行为、不可达分支、未闭环调用都标了「推断」并给出依据
- [ ] 断言未越界：订阅消息没有被写成触发功能，接口声明没有被写成存在调用方
- [ ] 没有臆造：每条结论都有证据；无证据处标注为待确认
- [ ] 独立自洽：本篇包含本主题完整结论与依据，不依赖其他文档才能读懂
- [ ] 主责清晰：本篇只展开主责内容，未复制其他篇的细节
- [ ] 表达易读：主语视角一致、主动语态、条件前置，无英文直译腔与弱写法
- [ ] 结构一致：同类型文档沿用同一骨架，术语全篇一致
- [ ] 覆盖完整：扫描维度逐项回答有或没有，未覆盖部分已说明
