# 阶段一：功能扫描

阶段一只读扫描，不修改任何文件，不执行会改变仓库状态的命令；遇到需要构建或安装依赖才能理解的项目，只读配置与锁文件推断，不执行安装、构建或测试。

## 定位步骤

1. 按功能名称搜索入口：HTTP 路由、RPC 方法、消息消费者、定时任务、事件监听器。
2. 从入口沿调用链追踪，记录涉及的文件、类、方法。
3. 识别外部交互：下游接口、消息、缓存、搜索、调度。
4. 识别数据存储：表、缓存结构、读写路径。
5. 识别异常处理与边界：错误码、失败处理、并发、幂等、超时。
6. 多项目时重复以上步骤，并识别各项目在功能中的角色与跨项目调用点。

## 扫描维度

| 维度 | 要找什么 |
|---|---|
| 定位与边界 | 功能做什么、不做什么、触发方式 |
| 流程与逻辑 | 主流程、关键分支、状态流转、业务规则 |
| 代码结构 | 入口、调用链、类与方法、文件位置 |
| 上下游 | 调用方、被调用方、外部接口 |
| 中间件 | 消息、缓存、搜索、调度 |
| 数据存储 | 表结构、缓存结构、读写路径 |
| 异常与边界 | 错误码、失败处理、并发、幂等、超时 |

中等功能走完一遍；大型功能或跨项目功能按链路抽样，并说明覆盖范围与未覆盖部分。

## 证据

结论要能回到代码或配置：给出路径、类名、方法名；行号无法可靠确认时不写。区分已核实与推断，证据不足标为待确认，不凭类名或注释断言功能已上线。

## 跨项目

输入多个项目时，先记录每个项目的路径与角色（入口方、服务方、数据方等），再按功能主线串联调用链。每处结论标注所属项目，不按项目边界切割文档。
