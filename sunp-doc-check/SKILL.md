# 文档表达审查

## 用途与边界

审查一份已有文档的表达层质量，给出可执行的改进建议；用户要求时按建议润色。用于写完后的自查或润色，不负责从零生成文档。

只处理表达、语法与阅读体验，不改文档的事实结论与技术内容。发现事实或逻辑问题时单独指出，交由用户确认，不擅自改写。

## 输入解析

调用时若随 skill 附带了文字（如 `/sunp-doc-check docs/设计说明.md` 中的路径），视为待审查的文档路径或内容描述；路径明确时直接读取，含糊时按流程先确认审查对象。没有附带文字时同样先问清楚。

## 流程

复制下列清单逐项推进，每项完成后再进入下一项：

```
- [ ] 确认审查对象：文件路径或用户贴出的内容；没有就先问清楚
- [ ] 通读一遍，判断文档类型与读者
- [ ] 按 references/ 的清单逐项检查，记录问题位置与具体表现
- [ ] 按影响排序输出：先看是否影响读者理解结论，再看语法与措辞，最后看格式
- [ ] 用户要求润色时，按建议改进并列出改动处
```

## 审查清单

按下列顺序逐项检查，只报确实存在的问题；不存在就跳过，不为凑数制造问题。各项细则见对应 reference。

| 顺序 | 审查项 | 细则 |
| --- | --- | --- |
| 1 | 读者与用途 | [`references/reader.md`](references/reader.md) |
| 2 | 结论与结构 | [`references/structure.md`](references/structure.md) |
| 3 | 中文语法与标点 | [`references/chinese.md`](references/chinese.md) |
| 4 | 句式与语态 | [`references/sentence.md`](references/sentence.md) |
| 5 | 阅读体验 | [`references/readability.md`](references/readability.md) |

发现事实或逻辑问题时单独列出，不计入表达层问题，交由用户确认。

## 输出

```
👉 结论
一句话给出总体判断：表达是否达标、主要问题是什么。

👉 问题清单（按影响排序编号）
1. <位置>：<问题> → 建议改法

👉 已改进（按需）
列出实际改动处；未要求润色时省略此节。
```

没有问题且用户未要求润色时，写「未发现表达层问题」并停止，不追加无关建议。
